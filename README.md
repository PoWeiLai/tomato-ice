# 蔗家店 — 掃碼點餐系統

客人掃桌上的 QRcode → 手機點餐 → 訂單即時進廚房看板 → 廚房照單製作 → 櫃檯結帳。
不需要服務生來回抄單。

## 每天開店怎麼用

在店內那台電腦開一個終端機，執行：

```bash
npm start
```

畫面會印出三個網址，例如：

```
店內網址   http://192.168.50.2:3001
廚房看板   http://192.168.50.2:3001/kitchen
外帶點餐   http://192.168.50.2:3001/takeout
後台管理   http://192.168.50.2:3001/admin   （店員密碼 1234）
```

- **廚房**：平板或螢幕開 `/kitchen`，整天掛著就好，新單會自動跳出來並響提示音
- **櫃檯/老闆**：開 `/admin` 改菜單、列印 QRcode、結帳
- **客人**：掃桌上 QRcode 進 `/t/桌號`
- **外帶**：掃櫃檯的外帶 QRcode 進 `/takeout`（電話外帶也可以由店員在櫃檯開這頁代點）

> 客人手機必須連上**店內同一個 WiFi**，否則掃了打不開。

## 第一次設定

1. `npm install`
2. `npm run build`（建置前端；改過前端程式碼才需要重跑）
3. `npm start`
4. 用瀏覽器開 `/admin` → 輸入密碼 `1234` → 到「菜單管理」把菜單建好
5. 切到「QRcode 列印」→ 按「列印全部 QRcode」→ 剪下貼在 1～10 號桌上

### 改店員密碼

密碼**只能是 4～8 位數字**（手機登入畫面用數字鍵盤，打不出英文）。
最簡單的方式是後台 →「今日報表」→「店員密碼」直接改，改完存在資料庫，重開也有效。

也可以用環境變數指定預設密碼（後台改過的話以後台為準）：

```bash
set STAFF_PIN=882266 && npm start        # Windows cmd
$env:STAFF_PIN='882266'; npm start        # PowerShell
```

### 忘記密碼

改完密碼後，**順便到同一頁的「老闆手機」登記手機號碼**。忘記密碼時，登入畫面按「忘記密碼？」，
輸入登記的手機號碼就能設定新密碼並直接登入。不發簡訊（不必申請簡訊服務、不用付費），
只是拿手機號碼當驗證問題，所以請登記老闆本人的手機，不要登記店裡公開的電話。
連續輸錯 5 次會鎖 15 分鐘。

沒登記手機的話就不能自助重設，只能找系統提供者用環境變數 `STAFF_PIN` 或直接改資料庫。
（也可以用環境變數 `OWNER_PHONE` 預先指定；後台登記過的話以後台為準。）

### IP 會變怎麼辦

路由器每次可能配不同 IP，QRcode 就失效了。建議在路由器把這台電腦設成**固定 IP**（DHCP 保留）。
若要指定固定網址，可用：

```bash
set PUBLIC_URL=http://192.168.50.2:3001 && npm start
```

## 菜單怎麼建

三種方式，挑一種：

1. **後台一道一道加** — `/admin` →「菜單管理」→ 先新增分類，再逐項填品名/價格
2. **整本貼上匯入** — 同頁最下方「批次匯入菜單」，每行一道：
   ```
   熱炒,宮保雞丁,180,微辣
   熱炒,蒼蠅頭,160
   飲料,烏龍茶,30
   ```
   格式是 `分類,品名,價格,說明`（說明可省略）
3. **改種子檔重灌** — 編輯 `server/menu.seed.json` 後執行 `npm run seed:menu`
   （會清空現有菜單再匯入，適合一次性建置）

**菜色照片**：在「菜單管理」每一列最左邊點「＋圖片」直接上傳，檔案會存到 `public/images/`。

目前 37 道菜中有 12 道帶照片，全部是從店家 DM 照片裁切出來的（`menu-source/` 是原始素材，
裁切腳本見下方）。**沒有照片的品項，客人端會自動顯示品牌色字卡**，不會出現空白破圖。
要補照片就用手機拍好，從後台該道菜的「＋圖片」上傳即可，不必改程式。

重新裁切菜單原圖的方式（需要 `sharp`，已列在 devDependencies）：

```bash
node -e "require('sharp')('menu-source/檔名.jpg').extract({left:0,top:0,width:300,height:200}).resize({width:600,height:450,fit:'cover'}).toFile('public/images/新檔名.jpg')"
```

## 選項（口味、配料、冷熱、甜度）

DM 上的「附加一料」「口味選擇」「冰沙／果汁」做成「選項群組」，定義在 `server/menu.seed.json` 的 `optionGroups`：

| 群組 | 必選 | 內容 |
| --- | --- | --- |
| 冰沙或果汁 | ✅ | 冰沙、果汁（芒果／西瓜／鳳梨／百香果／檸檬） |
| 雪花冰口味 | ✅ | 牛奶、草莓、芒果、抹茶、伯爵奶茶、巧克力、花生、檸檬（純雪花冰擇一；双味可複選兩種） |
| 附加一料／附加二料 | ✅ | 紅豆、綠豆、芋圓、粉粿、仙草、寒天、波波球、花生（免費） |
| 配料（黑糖刨冰） | 選填 | 三寶選 3 樣、五寶選 5 樣、八寶選 8 樣 |
| 加鮮水果 | 選填 | 不加 +0、加鮮水果 +20 |
| 冷／熱 | ✅ | 冰的、熱的（DM 上有 ▲ 的品項） |
| 甜度、冰塊 | 選填 | 正常／少糖／半糖／微糖，正常／少冰／去冰 |

> 配料清單是照一般冰店常見配料先填的，請對照店裡實際提供的配料到後台「菜單管理」修改。
> 「可複選」的群組目前不限制數量（客人選了 3 種口味也送得出去），廚房照單做即可。

每道菜在 `items[].options` 列出要掛哪些群組。例如純雪花冰：

```json
{ "name": "純雪花冰", "price": 70, "options": ["雪花口味", "附加一料"] }
```

- 客人點有選項的菜時，會跳出選單而不是直接加入購物車
- **必選沒選不讓送出**（例如雪花冰沒選口味）
- 加價一律由**伺服器**計算，前端傳來的價格不採信
- **同一道菜不同選法會分成兩列**（草莓雪花冰和芒果雪花冰各自計數）
- 廚房看板會把選項用大字印在品名下方，備註用紅字

改完選項或菜色後執行 `npm run seed:menu` 重新匯入。

## 日常操作

| 情境 | 怎麼做 |
| --- | --- |
| 某道菜賣完了 | 後台 →「標售完」，客人端立刻變灰、不能點 |
| 臨時調價 | 後台 →「改價」。**已送出的訂單不受影響**（下單當下就存了價格快照） |
| 客人加點 | 客人在同一個 QRcode 頁面再點一次即可，會併入同一桌帳單 |
| 外帶 | 客人掃櫃檯外帶 QRcode（或店員開 `/takeout` 代點），送單時留稱呼。廚房看板會標「外帶・稱呼 #單號」，帳單結帳頁每張外帶單各自一筆 |
| 打折／免單 | 「帳單結帳」每張帳單上先選「打折」（填 9 = 9折、85 = 85折）、「折抵金額」或「免單」，可填原因，再按付款方式結掉。帳單和報表都會記錄折扣 |
| 結帳 | 後台 →「帳單結帳」→ 選現金／刷卡／行動支付。結完該桌歸零，下一組客人重新開單 |
| 印帳單 | 「帳單結帳」→「列印帳單」 |
| 看今天做多少 | 後台 →「今日報表」，有營業額、桌數、熱銷排行 |

廚房看板：訂單等超過 15 分鐘會整張變紅色提醒。

## 開發

```bash
npm run dev        # 同時啟動後端 (3001) 與 Vite 前端 (5173)
npm run build      # 建置前端到 dist/
npm start          # 正式模式，單一 port 3001 同時供應前端與 API
npm run seed:menu  # 用 server/menu.seed.json 重灌菜單
```

## 架構

```
server/
  index.js       Express API：菜單、訂單、廚房、後台、QRcode、帳單
  db.js          SQLite schema（用 Node 24 內建 node:sqlite，免安裝原生模組）
  events.js      SSE 推播，廚房不必輪詢就能即時收單
  seed.js        菜單種子匯入
  menu.seed.json 菜單原始資料
src/
  views/TableOrder.vue  客人點餐（手機版；/t/桌號 內用、/takeout 外帶共用）
  views/Kitchen.vue     廚房看板
  views/Admin.vue       後台：菜單 / QRcode / 帳單（折扣、免單）/ 報表（改密碼、備份）
  api.ts                前端 API 封裝
data/restaurant.db      營運資料（含訂單與帳單，記得備份）
public/images/          菜色照片
```

### 資料表

- `tables` — 1～10 號桌；0 號是外帶保留桌，不會出現在 QRcode 與桌號列表
- `sessions` — 一桌從入座到結帳為一個 session，帳單以此結算；外帶每張單各自一個 session，並記錄折扣金額與原因
- `settings` — 店家設定（後台改過的店員密碼、忘記密碼用的老闆手機）
- `orders` / `order_items` — 訂單與明細，明細存下單當下的品名與價格
- `categories` / `menu_items` — 菜單

### 備份

後台「今日報表」頁按**「下載備份」**會拿到一份 JSON（每個資料表一個陣列，照片不含在內）。
本機模式的資料也都在 `data/restaurant.db` 這一個檔案，關掉程式後複製走即可。
用 Turso 的話，資料本來就在雲端，Turso 後台另外有還原點可用。

## 部署到雲端（交付給店家）

在店內電腦跑 `npm start` 的模式，電腦一關店家就不能點餐。若要交付給店家自行營運、
與開發者的電腦脫鉤，就把系統部署到 24 小時運作的主機上。

**資料放哪裡**：主機本身不一定有永久硬碟（Render 免費版就沒有），所以訂單、帳單、
店家上傳的照片、客人拍的回饋照片全部存在 **Turso**（雲端 SQLite，免費方案就夠一家店用）。
主機重啟、重新部署都不會掉資料。沒設 Turso 的話程式會退回用本機檔案 `data/restaurant.db`。

### 步驟

1. 把這個專案推上 GitHub
2. 建 Turso 資料庫（免費）：
   - 到 <https://turso.tech> 註冊 → **Create Database**，地區選 **Singapore**（離台灣最近）
   - 拿兩個值：**Database URL**（`libsql://xxx.turso.io`）和 **Token**（Generate Token，選不會過期的）
   - 也可以用 CLI：`turso db create restaurant --location sin`、`turso db show restaurant --url`、`turso db tokens create restaurant`
3. 主機（Render / Zeabur / 其他）建立服務，選 GitHub → 這個 repo
   （會自動偵測 `package.json`，跑 `npm run build` 再 `npm start`）
4. 設定環境變數：

   | 變數 | 值 | 用途 |
   | --- | --- | --- |
   | `TURSO_DATABASE_URL` | `libsql://xxx.turso.io` | 資料庫位置，**沒設就只會存在主機本機，重啟會掉** |
   | `TURSO_AUTH_TOKEN` | Turso 給的 token | 資料庫密碼 |
   | `STAFF_PIN` | 4～8 位數字 | 店員登入 `/admin`、`/kitchen` 的預設密碼（後台可再改） |
   | `OWNER_PHONE` | `0912345678` | 忘記密碼時用來驗證的老闆手機（可不設，直接在後台登記即可） |
   | `PUBLIC_URL` | `https://你的網址` | QRcode 裡要寫的網址（Render 不用設，會自動抓） |
   | `TABLE_COUNT` | `6` | 內用桌數（預設 6 桌），改了重啟即生效 |
   | `TZ_OFFSET_HOURS` | `8` | 報表分天用的時差，台灣是 +8（預設值，不用設） |
   | `TRIAL_END` | `2026-10-31` | 試用最後一天（預設 `2026-09-30`）；填 `0` 就不限期。見下方「試用期」 |

5. 開 Domain 拿到網址後，回填 `PUBLIC_URL` 再重新部署一次（Render 免）
6. 進 `/admin` →「QRcode 列印」→ 列印全部 → 貼到桌上
7. 打開 `https://你的網址/api/health` 確認：看到 `"db":"turso"` 就對了。
   若是 `"db":"file"` 並附一段 `warning`，代表 Turso 兩個值沒填或填錯，照 warning 的提示到主機
   環境變數頁修正（程式不會因此停掉，只是資料暫存主機本機、重啟會掉）。

目前線上：<https://tomato-ice-order.onrender.com>

### 第一次啟動會自動做的事

- 在 Turso 建好所有資料表、開內用桌與外帶保留桌
- 菜單是空的就自動匯入 `server/menu.seed.json`（8 個分類、37 道菜）
- 內建菜色照片跟著程式走（`public/images/`），店家後來上傳的才存進資料庫

所以部署完直接就能用，不必另外跑 `npm run seed:menu`。

### 交付後店家自己能做的事

改菜單、改價格、標售完、上傳照片、結帳、印帳單、看報表、重印 QRcode，
以及在「今日報表」頁按**「下載備份」**把營運資料存到自己的電腦（建議每月一次）。

### 試用期

系統內定試用到 **2026-09-30** 為止。店家在這一天（含當天）以前一切照用，
**10/1 凌晨起整站停用**：客人的點餐頁、廚房看板、後台都只會看到一頁「試用期已結束」，
所有 API 一律回 403（只留 `/api/health`，方便從外面確認主機還活著、期限設到哪天）。
以店家當地時間（`TZ_OFFSET_HOURS`，預設 +8）分日，主機不重啟也會在當地凌晨自動生效。

期限只能由部署的人改，店家在後台碰不到。到主機的環境變數頁改 `TRIAL_END`：

| 設定 | 結果 |
| --- | --- |
| 不設 | 2026-09-30 當天結束（內定） |
| `TRIAL_END=2026-10-31` | 延長到 10/31 當天結束 |
| `TRIAL_END=0` | 不限期，永久開放（正式交付就設這個） |

Render 的話是：服務頁 → **Environment** → 改這個值 → 存檔會自動重啟生效，已經鎖住的站會立刻打開。
剩 7 天以內時，廚房看板與後台頂端會出現提醒橫幅（客人的點餐頁不會顯示），程式在 `server/trial.js`。

### 注意

- 部署到雲端後，**店家網路斷線就不能點餐**（跑在店內電腦的模式則不受影響）
- 試用到期是**整站**鎖住，後台的「下載備份」也會一起停掉。要讓店家在到期後匯出自己的資料，
  先把 `TRIAL_END` 改成晚一點的日期再請他們下載
- 一定要設 `TURSO_DATABASE_URL`，否則資料只存在主機上，免費方案一重啟就清空
- 目前是單店設計。第二家店要另外開一個 Project，不能共用同一個網址

### 用 Render 部署（免費方案 + Turso）

專案根目錄的 `render.yaml` 已寫好設定，到 Render 按 **New → Blueprint** 選這個 repo
即可自動建立服務，建立時會問你 `TURSO_DATABASE_URL` 和 `TURSO_AUTH_TOKEN`，把 Turso 給的值貼上。
已經建好的服務則到 Render → 該服務 → **Environment** 手動加這兩個變數，存檔會自動重新部署。
`PUBLIC_URL` 不用設，程式會自動讀 Render 提供的 `RENDER_EXTERNAL_URL`，QRcode 就會指向線上網址。

啟動 log 第二行會印「資料庫 Turso（雲端，永久保存）」，看到這行才代表有接上。

Render 免費方案本身的限制：

- 15 分鐘沒流量就休眠，下次開啟要等約 1 分鐘
  （程式在 Render 上會每 10 分鐘自己喚醒自己一次，平常不太會睡；不想要可設 `KEEP_AWAKE=0`）
- 每月 750 小時額度
- 沒有永久硬碟——但資料都在 Turso，所以重啟、重新部署都不影響訂單與照片
